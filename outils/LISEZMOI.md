# Outils de Claude

Des scripts pour les gestes qui reviennent à chaque vidéo (demande de Kev, 2026-11-08 : moins d'actions, moins de tokens). On les lance depuis la racine de l'agence, ou on donne leur chemin complet. **Chaque outil répond à `--help`** (sans rien lancer ; `colab_lib.sh`, `voix_colab.py` et `whisper_colab.py` sont appelés par les autres, jamais seuls) (son mode d'emploi, rien n'est lancé) : le lire au lieu d'ouvrir le code (Kev, 2026-11-20 : moins de tokens).

| Outil | Ce qu'il fait | Exemple |
|---|---|---|
| `chaine.sh` | **BÊTA** — **la chaîne d'un épisode** (étapes 5 à 9) en 4 temps : `fixes` (image au milieu de chaque plan, à relire), `rendu` (un seul rendu, courtes d'abord), `finition` (son, mux, miniatures, copies téléphone, rangement), `controles` (bandes, sous-titres, physique, Earshot, synchro, à relire) | `bash outils/chaine.sh <épisode> fixes` |
| `fixes.py` | (sur la machine Google, lancé par chaine.sh) les planches d'images fixes, une par plan ; accroches à 0 / 0,5 / 1,2 / 3 s ; avec `long` : `miniature-comparaison.jpg` (notre miniature + `00-sujet/miniatures-ref/*.jpg`), le test de l'inconnu avant les rendus longs (2026-11-23, pas encore passé sur une vraie machine) ; `--help` | — |
| `rendu_colab.sh` | rend une ou plusieurs vidéos sur la machine Google (carte T4), le PC ne calcule pas ; tout dans un seul appel ; `--help` | `sh outils/rendu_colab.sh 05-rendu/film 05-rendu/L006-rendu-muet.mp4` (depuis l'épisode) |
| `atelier_colab.sh` | **l'atelier Google** : une machine avec Lemo + instruments, Earshot, whisper, ffmpeg, et les fichiers de l'agence aux mêmes chemins que sur le PC ; on y envoie l'épisode, on y lance son, mux, miniatures, contrôles, on rapatrie les finales (Kev, 2026-11-19 : le PC n'est qu'une télécommande) ; `CPU=1` : machine sans carte graphique, à côté d'une machine qui rend ; `--help` | `bash outils/atelier_colab.sh start` puis `envoie`, `lance`, `whisper`, `rapatrie`, `stop` |
| `finir_atelier.sh` | finit **une** vidéo déjà rendue (muette) sur l'atelier : envoie le dossier du LSO, vérifie là-bas ses entrées, son, mux, miniature, `.srt`, copie téléphone, contrôle, rapatrie et range dans `<CODE>-LSO/` ou `<CODE>-Extraits/` ; montre la vraie trace en cas d'échec | `bash outils/finir_atelier.sh nan_serieux/en/episodes/L006-black-friday LSO2` |
| `rendu_lot.sh` (dans `09-export/` de L006, modèle) | rend toutes les vidéos d'un épisode (longue, extraits, LSO, FR et EN) en un seul appel à `rendu_colab.sh`, en bash (zsh ne coupe pas une liste) ; lire `colab.log` avant de dire fini | `bash 09-export/rendu_lot.sh [longue-en]` |
| `colab_lib.sh` | (chargé par les outils Google, pas lancé seul) `cx` : commande courte avec limite de temps et 3 essais ; `cjob` : travail long lancé détaché là-bas et suivi par son journal — plus aucune commande ne peut rester figée (2026-11-19) | — |
| `image.mjs` | une image d'un film (miniature, contrôle) qui marche aussi sur la machine sans carte graphique (`still.mjs` abandonne au bout de 30 s) | `node outils/image.mjs LSO1/05-rendu/film 2.2 mini.jpg --q 'v=1&ext=LSO1&nosub=1' --size 1080x1920` |
| `changer_compte_colab.sh` | passe le Colab CLI sur un autre compte Google quand le quota de carte graphique est épuisé ; à lancer dans un onglet du Terminal, Kev se connecte et colle le code | `bash outils/changer_compte_colab.sh` |
| `verif_gpu.sh` | dit en une ligne si Google donne une carte graphique maintenant (GPU OK / refusée / compte non connecté) ; `--changer` change d'abord de compte puis vérifie | `bash outils/verif_gpu.sh [--changer]` |
| `medias.py` | télécharge les vrais médias d'un épisode (vidéos : seulement le passage utile, 1080p au plus ; images) d'après son annuaire `01-recherche/MEDIAS.md`, dans `~/agence-medias/<chaîne>/<CODE>/` (hors de Git, pas dans /tmp) ; ne retélécharge jamais un fichier présent ; `--liste` ; `--help` (MEMOIRE règle 42) | `python3 outils/medias.py nan_serieux/fr/episodes/F002-gta6` |
| `envoie_medias.sh` | envoie les médias utilisés par le montage (`05-rendu/reels.json`) du PC vers une machine Google, en morceaux de 40 Mo recollés et vérifiés (YouTube bloque `yt-dlp` sur les machines Google) ; `--help` | `bash outils/envoie_medias.sh nan_serieux/fr/episodes/F002-gta6 atelier2` |
| `incruste.py` | pose les vrais extraits SOUS le film rendu par écran vert (le film peint `#00FF00` là où va le vrai ; sous-titres et cadres restent dessus), d'après `reels.json` (début dans le film, début dans la source, durée, rectangle, recadrage, volume) ; `--son` sort aussi le son des extraits pour le mixage ; sur Google pour un film entier ; `--help` | `python3 outils/incruste.py muet.mp4 reels.json sortie.mp4 --son reels-son.wav` |
| `capture.mjs` | capture d'une page web publique (article, page de notes) en image, avec le Chrome de Lemo, sur la machine Google ; refuse les cookies non nécessaires ; `--sel` pour un seul élément ; `--help` | `node outils/capture.mjs https://… sortie.png --size 1600x1000` |
| `attendre_gpu.sh` | attend que Google donne une carte graphique (vérifie toutes les 10 min, abandonne après 6 h), puis rend la main : à mettre en tête d'une chaîne `enchaine.sh` quand Google refuse la T4 ; `--help` | `bash outils/attendre_gpu.sh 6 10` |
| `copie_telephone.sh` | copie d'une vidéo finie sous 30 Mo pour le téléphone de Kev, faite sur une machine Google sans carte graphique | `bash outils/copie_telephone.sh <video.mp4> [sortie.mp4]` |
| `rendu_morceaux.sh` | rend un long film (ou un extrait) par morceaux de 90 s sur Google (machines reprises au bout de ~12 min, réseau du PC qui coupe) ; relancé, il reprend où il s'est arrêté, puis recolle sans réencoder. **Pour REFAIRE une image : `REFAIRE=1`** (sinon il recolle les vieux morceaux ; il refuse de lui-même si le film a changé depuis, 2026-11-22) ; `--help` | `bash outils/rendu_morceaux.sh <film> <sortie.mp4> [LxH] [requête]` |
| `voix_colab.sh` | voix maison + contrôle whisper sur la machine Google ; `--help` | `sh ~/agence-video/outils/voix_colab.sh fr` (depuis `03-voix/`) |
| `bandes.py` | (sur l'atelier) bandes à 0,2 s (revue technique, étape 7) : une image par plan, 5 images par seconde | `python3 outils/bandes.py video.mp4 04-decoupage/decoupage.json 07-revue-technique/bandes` |
| `rendu.sh` | (seulement si Google est indisponible) lance un long rendu sur le PC sans risque : 1 worker, garde batterie (rendu figé sous 25 % en décharge, repris à 40 %), mise en veille bloquée, température et batterie notées chaque minute dans `~/.cache/rendu-temp/` | `sh ~/agence-video/outils/rendu.sh sh 05-rendu/build.sh` |
| `rendu_partiel.py` | refait seulement les plans cités d'une vidéo déjà rendue et les recolle au reste (copié sans réencodage, coupé sur les images clés) ; vérifie le nombre d'images et le décodage, sinon garde l'ancienne vidéo (Kev, 2026-11-14). Rendu complet quand la voix, le découpage ou un fichier commun changent, et pour la version finale | `python3 ~/agence-video/outils/rendu_partiel.py 45 '41 ✦'` (depuis l'épisode) |
| `synchro.py` | synchro voix ↔ image d'une vidéo finie, mesurée sur le signal toutes les 30 s : voix → voix de montage → son du `.mp4` (Kev, 2026-11-09) | `~/lemo-opuscar/.venv/bin/python outils/synchro.py 06-son/L003-v1.mp4` (depuis l'épisode) |
| `soustitres.mjs` | textes pixel cachés par les sous-titres (Kev, 2026-11-09) : liste chaque texte dont la boîte touche celle du sous-titre, avec ses temps ; `--croise` : aussi deux textes l'un sur l'autre ; `--sans3d` : sans dessiner la 3D (machine sans carte graphique, si le film lit `window.NO3D`) ; le film doit exposer `window.SUBTX(t)` (voir `main.js` de L003) | `node outils/soustitres.mjs <épisode>/05-rendu/film` |
| `physique.mjs` | logique physique mesurée dans la 3D : deux personnes l'une dans l'autre, un corps dans un meuble, un objet au-dessus de quelqu'un, regroupé par plan (à vérifier ensuite sur les bandes) ; `--sans-image` : sans dessiner (machine sans carte graphique, si le film lit `window.NODRAW`) | `node outils/physique.mjs <film> --sans-image [--q 'v=1&ext=LSO1' --size 1080x1920]` |
| `controle.sh` | contrôle des vidéos finies : durée, volume (−14 LUFS), images figées plus de 2,5 s, écrans noirs, poids | `sh outils/controle.sh L001/*.mp4` |
| `planche.sh` | (sur l'atelier) planche de revue : une image toutes les N secondes (1,5 par défaut), 8 par ligne | `sh outils/planche.sh video.mp4 planche.jpg 1.5` |
| `finir_lso.sh` | la finition de plusieurs LSO en une commande : vérifie la machine (sur la machine, pas sur un fichier), envoie l'épisode, `finir_atelier.sh` de chacun, `livrer.py` ; `--help` | `bash outils/finir_lso.sh nan_serieux/fr/episodes/F001-jensen-huang LSO1 LSO2` |
| `miniature_film.sh` | la miniature 16:9 d'un film (scène `thumb`), sur la machine sans carte ; ramène `09-export/<CODE>-miniature.jpg` ; à regarder à l'œil (test de l'inconnu, MEMOIRE 39) ; `--help` | `bash outils/miniature_film.sh nan_serieux/fr/episodes/F001-jensen-huang` |
| `controles_lso.sh` | sous-titres (`--croise --sans3d`) puis physique (`--sans-image --step 1`) d'un ou plusieurs LSO, sans carte graphique ; `--help` | `bash outils/controles_lso.sh nan_serieux/fr/episodes/F001-jensen-huang LSO1 LSO2` |
| `recoller_son.sh` | image d'une vidéo récente + son d'une vidéo finie, sans réencoder (`ffmpeg -c copy`) ; refuse si les durées diffèrent ; évite d'envoyer un muet de plus de 300 Mo à Google ; `--help` | `bash outils/recoller_son.sh 05-rendu/F001-rendu-muet.mp4 F001/F001-jensen-huang.mp4 /tmp/nouveau.mp4` |
| `enchaine.sh` | enchaîne des commandes dans un journal (une ligne par étape, arrêt à la première erreur) : plus de script jetable à chaque fois ; **`<journal>.etat` : une ligne d'état (EN COURS 2/3 / BLOQUÉ / FINI) à lire pour répondre à « ça avance ? », et une notification de bureau à la fin ou à l'erreur** (2026-11-23) ; `--help` | `nohup bash outils/enchaine.sh /tmp/suite.log "LSO1::bash outils/finir_lso.sh … LSO1" &` |
| `livrer.py` | range les livrables d'un épisode (`PRODUCTION.md`, « Le dossier d'un épisode ») et refuse de finir s'il manque une miniature, un `.srt`, un fichier de textes ou une section ALT ; ne touche jamais à un épisode terminé | `python3 outils/livrer.py nan_serieux/fr/episodes/L003-slug` |

Quand une commande revient souvent à la main, elle devient un outil ici, et une ligne s'ajoute à ce tableau.
